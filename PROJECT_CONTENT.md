# Project feature and workflow content

The detail tabs read `src/data/projects/project-details.ts`. Keep this information
specific to demonstrated functionality. Do not infer guarantees from a dependency,
planned feature, screen name, or generated overview alone.

Sources reviewed for this revision:

- **VECPRO:** existing case study and dashboard screenshots; `xelpaxu/aedex`
  capture, results, tanod reports, and `docs/TANOD_ACCESS.md`. The original Aedify
  repository URL was unavailable. The separate `aedify-vite` demo was not treated
  as proof of the production dashboard implementation.
- **VISAIA:** `kheypaxu/visaia/PROJECT_SUMMARY.md`, source-tree modules, and
  `docs/offline-validation.md`. Device-local persistence is not described as an
  always-running background upload service.
- **VISAIA Dashboard:** `kheypaxu/visaia-dashboard/PROJECT_OVERVIEW.md`, current
  `src/config/navigation.tsx`, and the available route/component inventory.
  Speculative future AI and infrastructure claims were excluded.
- **Amogus:** `xelpaxu/amogus/src/pages/GameScreen.tsx`,
  `server/zrok_game_server.py`, and `server/model_api.py`. These show the three
  response stages, room events, timer, and embedding-based outlier comparison.
- **Memowee:** `xelpaxu/Memowee/memowee_backend.py` plus the existing case study.
  The content describes a prototype, not verified identification accuracy.
- **Vertex Realty:** collection and property-detail source files in
  `xelpaxu/vertex-realty` plus the existing case study.
- **CICTZONE:** `xelpaxu/cictzone/game_objects.py`, repository module inventory,
  and the existing case study. Features can vary between game implementations.
- **BigBrew POS:** `xelpaxu/BIGBREW-POS/views/order_window.py`,
  `views/reports.py`, module inventory, and the existing case study.
- **enCast:** existing specification-derived case study. New copy continues to
  identify this scope as documented design rather than verified implementation.
- **NexaCare / Revia:** existing case studies. Their repository links redirected
  to unavailable resources; do not add new modules, payments, permissions, or
  other claims without updated sources.

Feature groups and named journeys can be extended independently. Workflow steps
contain an actor, an action, and an output; outputs describe the flow rather than
claiming production reliability or measured impact.
